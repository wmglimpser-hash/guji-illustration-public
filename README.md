# 中医古籍插图 AI 辅助整理工具

中医古籍中的药物、诊法、经穴、脏腑、医疗与养生插图，长期分散在不同书籍、版本和页面之中。本项目尝试建立一套面向中医古籍插图的数字化整理工作流，在保留书—卷—页—图来源关系的基础上，结合 AI 候选生成与专家审核，形成可检索、可回看原页、可追溯修改过程的结构化记录。

## 在线体验标注系统

**[打开标注系统在线 Demo](https://wmglimpser-hash.github.io/guji-illustration-public/)**

通过《补遗雷公炮制便览》卷3的真实本地工作快照，浏览全卷160页、160页OCR、32页人工修订及96个已确认插图页。128条标注记录保留112条已确认的当前图项和16条拆分前的整页历史记录。可查看选框、分图、AI初稿、当前标注、图文证据和审核修改。体验修改保存在当前浏览器，可恢复到发布时的工作快照。建议使用电脑浏览。

完整的导入、OCR、模型调用和本地数据保存，请按下方“快速开始”运行本地标注系统。

本工具坚持“AI 辅助、专家主导”：模型输出是待审核候选，不作为未经核验的学术结论；人工终稿与 AI 初稿分别保存，便于回溯整理过程。

> **评价口径声明**：本工具追踪 AI 候选与人工终稿的字段差异，但该差异不等于模型准确率。人工终稿在阅读候选后形成，二者不具备独立性；在缺少独立参考集与盲态评判流程的前提下，本项目不报告 AI 识别准确率，也不据此主张人机协同比纯人工更高效。

- 导入古籍 PDF 或连续图像，建立书、卷、页索引
- OCR 与参考文本并置校文，保留原始文本和整理稿
- 裁剪、合并并确认插图范围
- 生成插图分类、主要对象、画面描述和最小原文证据候选
- 专家逐条审核，记录字段修改与来源上下文
- 导出结构化数据，并生成配套展示站

> 本工具在 AI 辅助编程支持下完成开发，作者负责研究设计、分类体系、标注规范、专家审核与研究结论。

> 本仓库是经过白名单筛选的公开代码镜像，仅 `online-demo/` 附卷三160页原书图像和该卷真实工作快照，不包含完整生产标注库、古籍 PDF、论文稿件或研究冻结数据。数据与图像边界见 [RIGHTS.md](RIGHTS.md)。

## 方法特点

- **来源可回指**：记录书名、卷次、页码、插图编号和原页位置。
- **图文联合整理**：插图与对应原文、OCR 和人工整理稿保持关联。
- **候选与终稿分离**：AI 草稿不覆盖专家审核后的终稿。
- **过程可追溯**：保留版本上下文和审核事件，支持复核整理过程。
- **评价口径克制**：未记录修改只表示生产流程中没有可检测差异，不构成正确性判断。

## 项目组成

| 模块 | 用途 |
|---|---|
| `online-demo/` | 无需后端的真实工作快照体验版 |
| `demo/` | 本地导入、OCR、插图确认、标注和校文工作台 |
| `showcase/` | 面向公众和研究者的只读展示站 |
| `specs/` | 对外公开的分类体系规范 |
| `scripts/` | 数据检查、导出和发布辅助脚本 |

## 快速开始

环境要求：Python 3.9+，现代浏览器（推荐 Chrome 或 Edge）。

```bash
git clone https://github.com/wmglimpser-hash/guji-illustration-public.git
cd guji-illustration-public
python -m pip install -r demo/requirements.txt
python demo/bridge.py
```

然后访问 `http://127.0.0.1:5678/`。

API Key、本地 PDF、OCR 结果和标注数据均应保存在本地配置或数据目录中，不应提交到公开仓库。
